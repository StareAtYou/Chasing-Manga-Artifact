# v0.3.5 下载、清理和来源阅读优化

## 行为变化

- 移出书架时，一次取消这部作品各关联来源的任务，批量删除下载记录；先将对应离线目录移出可读路径，再在后台回收文件，避免逐话反复扫描、调度整个队列。磁盘空间随后台清理释放；应用重启后会继续清理已提交的删除。
- 删除失败会保留完整的离线文件，将受影响的活动任务置为可恢复的暂停状态。若应用在移动目录与提交数据库之间退出，下次启动先恢复仍有下载记录的目录。
- 图片并发下载，全局最多 6 个图片请求，同一来源最多 3 个；最多运行 4 个章节任务，每部漫画最多占 2 个。章节准备每部并发 2 个，全局最多 4 个。保留阅读/搜索的请求名额，优先满足正在阅读的页面。
- 不同漫画各自保存准备进度、错误和取消状态；另一部漫画准备或下载时，仍可点击本部的整部下载。同一漫画重复点击会合并，移出一本书不会取消其他书的准备。第一话入队后就更新书架，不必等待全目录准备完成；不再逐章刷新整库。
- 搜索结果自动选择已显示的来源。点击来源卡片的资料区或空白区，直接续读该来源的进度，或从首个可读章节开始；目录、下载、关注及解除关联保持独立操作。受限章节不会自动开启，无可用在线内容时仅使用校验通过的完整离线内容。
- 继续保留章节衔接、整部下载补齐、暂停续传、图片校验、离线阅读、关联来源和阅读记录。已有数据库与离线目录无需迁移。

## 性能对照

使用相同本地样本与工具链，测量操作入口完成时间：

| 场景 | 修改前 | 修改后 |
| --- | --- | --- |
| 清理 120 个待下载章节 | 约 1.38 秒 | 约 0.008 秒 |
| 12 张图片，每请求固定模拟网络等待 | 约 0.26 秒 | 约 0.075 秒 |
| 移出含 1024 个离线文件的目录 | — | 约 0.003 秒，实际文件后台删除并检查已回收 |

这些是固定样本的对照结果，不是所有漫画源的速度承诺。实际速度仍取决于来源响应、限速、设备、图片大小和网络状况。

## 验证范围

214/214 项共享检查与 `swift test` 的 33 个参数化测试入口通过（覆盖范围有重叠，不将数量相加）。共享检查覆盖图片并发上限、第二部漫画在第一部完成前下载、暂停续传、批量删除不重新启动待删任务、后台文件回收、删除失败与重启恢复、独立准备和取消，以及来源卡片的阅读导航。

macOS 原生独立样本已验证卡片空白区进入阅读、关注开关不触发阅读、整部下载进入管理页、目录按钮进入章节列表。XCTest UI 脚本随新交互更新；未将 UI 自动化脚本计作已执行通过。

0.3.5（build 11）已通过 macOS Universal（Apple Silicon / Intel）和 iOS 设备 Release 构建、严格签名检查及压缩包完整性检查；iOS 包已在连接的 iOS 18.5 设备覆盖安装并成功启动。手机本次验证范围为安装和启动，下载调度及清理的并发场景由上述自动检查覆盖。

构建继续固定使用 Xcode 16.4，最低 macOS 14 / iOS 17，兼容现有 macOS 15.7.7 / iOS 18.5；不升级设备系统。测试样本、安装包、设备日志、签名和 Team 资料只留在本地。
