# v0.3.7 瓜子漫画章节 403 修复

## 症状与处理

iOS 点击瓜子漫画来源的“斗破苍穹”卡片后进入阅读器，但显示“无法打开章节 / HTTP 403”。单独在 Mac 解析目录成功不能代表手机的章节请求能通过。

原来的章节 HTML 请求仅包含 URL，没有作品页 Referer；403 会直接终止阅读。现在瓜子漫画的章节请求补充作品页 Referer 与 HTML Accept。正常响应仍走原有快速 HTTP 解析；只有 403 才尝试使用 App 已有的内置浏览器打开同一个公开章节，并提取原站正文区域。正文 DOM 完整且已出现正文图片后即捕获页面，不再等待图片等慢资源全部加载；提取后停止多余的浏览器资源传输。

- 校验浏览器最终 URL 仍属于同源、同一章节或分页，不接受其他章节替代。
- 保留实际浏览器的公开 User-Agent 和来源隔离的访问上下文；Cookie 仍由访问上下文按来源与域名匹配，不直接复制到图片 CDN。
- 同一来源的浏览器回退串行执行，避免同时阅读和下载准备互相导航、取消；图片并发预算保持 v0.3.6 的设置。
- 登录页与验证页仍提示登录或验证，不当作漫画内容；不改变受限章节的访问要求。
- 页面 ID、页序、离线文件、书架和阅读记录格式保持兼容，无需清空资料或迁移数据库。

## 验证范围

226/226 项共享检查与 `swift test` 的 36 个参数化入口通过，覆盖范围有重叠。新增回归检查先在旧实现复现失败，再验证正常阅读上下文、403 浏览器恢复、登录/验证页面、错误章节拒绝、同源并发回退及无浏览器时的原始错误保留。另用真实本地 HTTP 服务故意阻塞图片响应，验证 WebKit 在图片未完成前已提取完整 DOM，避免回退后的资源等待超时。

真实原生探针强制让普通 HTTP 章节请求返回 403，再通过真实 WebKit 打开原站，取得第 01 章完整 36 页、浏览器上下文和 User-Agent，并验证首张图片 HTTP 200、800×1426 可解码。使用手机数据副本，在完整“来源卡片 → 阅读器 → 图片管线”流程中强制章节 HTTP 403，也已恢复第 01 章 36 页并解码首图。

iOS UI 自动化未能执行：本机 Xcode 的 scheme 目标提示缺少可用 iOS 平台组件；不将此计作 UI 验收通过。最终 0.3.7（build 14）Release 使用设备 SDK 单独构建，已覆盖安装至连接的 iOS 18.5 手机，确认版本、成功启动并核对进程持续运行；手机上该章节的实际打开结果待用户复测。

构建固定 Xcode 16.4，支持现有 macOS 15.7.7 / iOS 18.5，设备系统未升级。签名、设备标识、手机资料副本与原始诊断日志只留在本地忽略目录。
