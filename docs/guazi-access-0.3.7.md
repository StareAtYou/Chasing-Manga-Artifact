# v0.3.7 瓜子漫画章节访问处理与真机复测

## 症状与处理

iOS 点击瓜子漫画来源的“斗破苍穹”卡片后进入阅读器，但显示“无法打开章节 / HTTP 403”。单独在 Mac 解析目录成功不能代表手机的章节请求能通过。

原来的章节 HTML 请求仅包含 URL，没有作品页 Referer；403 会直接终止阅读。现在瓜子漫画的章节请求补充作品页 Referer 与 HTML Accept。正常响应仍走原有快速 HTTP 解析；只有 403 才尝试使用 App 已有的内置浏览器打开同一个公开章节，并提取原站正文区域。正文 DOM 完整且已出现正文图片后即捕获页面，不再等待图片等慢资源全部加载；提取后停止多余的浏览器资源传输。

- 校验浏览器最终 URL 仍属于同源、同一章节或分页，不接受其他章节替代。
- 保留实际浏览器的公开 User-Agent 和来源隔离的访问上下文；Cookie 仍由访问上下文按来源与域名匹配，不直接复制到图片 CDN。
- 同一来源的浏览器回退串行执行，避免同时阅读和下载准备互相导航、取消；图片并发预算保持 v0.3.6 的设置。
- 登录页与验证页仍提示登录或验证，不当作漫画内容；不改变受限章节的访问要求。
- 页面 ID、页序、离线文件、书架和阅读记录格式保持兼容，无需清空资料或迁移数据库。

## 验证范围

227/227 项共享检查与 `swift test` 的 36 个参数化入口通过，覆盖范围有重叠。新增回归检查先在旧实现复现失败，再验证正常阅读上下文、403 浏览器恢复、登录/验证页面、错误章节拒绝、同源并发回退及无浏览器时的原始错误保留。另用真实本地 HTTP 服务故意阻塞图片响应，验证 WebKit 在图片未完成前已提取完整 DOM，避免回退后的资源等待超时。

在 Mac 上运行的真实原生探针强制让普通 HTTP 章节请求返回 403，再通过真实 WebKit 打开原站，取得第 01 章完整 36 页、浏览器上下文和 User-Agent，并验证首张图片 HTTP 200、800×1426 可解码。在 Mac 上使用手机数据副本，在完整“来源卡片 → 阅读器 → 图片管线”流程中强制章节 HTTP 403，也已恢复第 01 章 36 页并解码首图。

iOS UI 自动化未能执行：本机 Xcode 的 scheme 目标提示缺少可用 iOS 平台组件；不将此计作 UI 验收通过。0.3.7（build 14）Release 使用设备 SDK 单独构建，已覆盖安装至连接的 iOS 18.5 手机，确认版本、成功启动并核对进程持续运行。随后用户复测仍失败，手机错误页为“解析方式不匹配：缺少正文区域”，因此不认定为真机阅读验收通过。

构建固定 Xcode 16.4，支持现有 macOS 15.7.7 / iOS 18.5，设备系统未升级。签名、设备标识、手机资料副本与原始诊断日志只留在本地忽略目录。

## 真机失败原因复核

真机独立诊断确认，普通网络请求和内置 WebKit 都收到了原站 nginx 的 `403 Forbidden` 错误页（浏览器 DOM 仅 138 字节），并非缺失某个正文选择器。首页、作品页、章节页均存在拒绝，改用桌面或手机浏览器标识，以及先首页再章节的浏览顺序，均未恢复。原逻辑没有识别浏览器中的这类错误页，因而将访问拒绝误报为正文解析失败；现已保留为 HTTP 403，并添加回归检查。

Mac 按系统代理访问同章为 HTTP 200；在单次诊断请求中禁用代理、直接访问时，同样为 HTTP 403。这里只调整诊断请求的连接配置，没有修改电脑或手机的系统网络设置。此前原生 Mac 探针成功不能证明手机直连原站可用。用户先前确认能访问的 Safari 实际运行在 Mac；用户随后在连接的 iPhone 上用 Safari 打开同章，也确认返回 403。此处尚不能认定手机章节访问已恢复，也未将设备、代理或出口地址写入公开文档。

要完成手机阅读验收，需先让手机 Safari 在原站允许的网络环境中正常打开该章节，再复测 App。错误页识别补丁不承诺消除原站访问限制，也没有增加网络代理或转发服务。

错误页识别补丁构建为 0.3.7（build 15），共享检查 227/227 与原生测试 36 个入口通过；iOS / macOS Release 包均构建成功并验证签名和归档完整性。iOS 最低版本仍为 17.0，使用 iphoneos18.5 SDK；手机章节访问仍受上述原站 403 限制。
