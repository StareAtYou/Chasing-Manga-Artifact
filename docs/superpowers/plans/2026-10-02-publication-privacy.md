# 公开提交脱敏实施计划

> **For agentic workers:** 使用 superpowers:executing-plans 按任务执行；完工后进行一次独立审查。

**Goal:** 保持现有漫画功能和双端版本兼容，将脱敏后的完整源码提交到已配置的远程仓库。

**Architecture:** 仅修改仓库发布配置、说明和未发布提交元数据；用户签名配置、证书、设备专用 IPA 和应用数据留在本机。保留已发布历史，使用可回退的本地备份处理未发布历史，通过普通快进推送发布。

**Tech Stack:** Git、Swift 6.1、Xcode 16.4、Gitleaks。

**Spec:** 当前用户要求：保证现有功能不受影响，对项目脱敏，然后提交到远程仓库。

## Global Constraints

- 不改变 Sources、Apps 和 Tests 的功能实现或部署下限：iOS 17 / macOS 14。
- 不升级 Mac 或手机操作系统；保持现有本机签名安装能力。
- 不推送证书、私钥、设备标识、个人路径、应用数据或设备专用 IPA。
- 不覆盖远程已发布历史，不使用强制推送。

## Review Focus

- Git 历史与提交元数据同样属于发布内容。
- 测试用 Cookie、固定签名样本及图标文件名不是实际凭据，不破坏测试语义。
- 忽略规则不删除用户安装包或签名材料。
- 本机 Team 配置不进入公开提交。
- 推送只能包含已审查的历史与树，工作副本和远程内容应一致。

### Task 1: 清点与发布配置

- [x] 扫描全部跟踪文件、未发布历史与提交身份。
- [ ] `.gitignore` 排除个人签名、安装包、导出选项、数据库与环境文件。
- [ ] `docs/publication-privacy.md` 记录范围、保留规则和验证结果，不记录实际敏感值。
- [ ] 保留生产代码与测试代码的原始哈希，确认变更范围。

### Task 2: 脱敏历史

- [ ] 备份未发布本地历史，使用 GitHub 公开身份重建提交元数据，保留树、提交顺序与时间。
- [ ] 扫描预定推送历史的实际凭据、敏感标识和提交身份。
- [ ] 验证已发布 main 仍为祖先，普通推送可快进。

### Task 3: 功能验证与发布

- [ ] 执行共享原生测试、117 项共享检查、双端原生 Release 构建。
- [ ] 独立只读审查发布配置、历史与本机签名保留。
- [ ] 普通推送到 origin/main，读回远程 SHA 并确认发布内容。
- [ ] 更新源码交付副本和本地 main，保留设备专用安装包不变。
