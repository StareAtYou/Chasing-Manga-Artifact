# macOS / iOS 追漫应用设计

日期：2026-10-02

状态：需求讨论后的设计稿，供用户审阅；尚未批准实现计划。

## 1. 产品目标与已确认范围

提供面向普通用户的 macOS / iOS 漫画阅读和追更应用。首版公开开源，用户自行编译安装；以后按需要考虑上架。采用 Swift + SwiftUI，两端共享业务核心，分别适配界面。

用户已确认：

- 内置漫画网站源，允许用户添加自定义源。
- 自定义源自动尝试应用内置解析方法；验证成功后绑定，后续直接使用该方法。
- 跨源搜索，同一漫画可以关联多个来源，由用户选择来源后进入阅读。
- 书架、阅读历史、阅读进度、更新检查与提醒、离线下载。
- 竖向滚动和左右翻页、阅读方向切换、macOS 双页模式。
- 两端都是本地单机模式。源配置、书架、进度、缓存和下载各自独立；首版不提供账户、服务器或双端同步。

成功的核心体验：用户搜索作品，选择来源，加入书架并阅读；退出后能恢复位置；下载完成的章节断网可读；更新列表能展示所选来源的新章节；自定义源的有效解析绑定可复用。

## 2. 建议默认值与首版边界

以下是为形成可执行设计而提出的默认值，用户可在审阅时修改：

- 最低系统版本暂定 iOS 17、macOS 14；支持浅色、深色和跟随系统。
- iOS 优先适配 iPhone，提供可在 iPad 使用的自适应布局；iPad 专属多窗口体验不列为首版验收项。
- 默认阅读模式为竖向滚动，默认翻页方向为从左向右；按作品保存用户的阅读偏好。
- 用户自定义源首版输入名称和网站 URL，可选提供漫画详情或章节样本 URL；不要求用户编写规则，也不提供用户脚本编辑器。
- 新解析器通过开源代码贡献并随应用发布。首版不提供远程可执行插件、社区源市场、AI 在线生成解析代码。
- 自动作品关联只提供候选；用户确认合并或拆分。不同来源不自动替换正在阅读的内容。
- 更新提醒默认关闭，由用户启用。默认开启应用时检查书架更新，提供手动刷新；后台检查以系统允许的机会为准。
- 不包含自动裁边、跨页识别、自动滚动、漫画翻译、社交或推荐算法。
- 开源许可证建议 MIT，仅针对项目代码；最终选择在发布前确认，不替第三方内容授予权利。

## 3. 页面与操作流程

### 3.1 双平台导航

iOS 使用底部导航：书架、发现、更新、下载；源管理和设置从发现及全局设置入口进入。macOS 使用侧栏提供相同入口，内容区适配窗口大小。macOS 支持搜索、翻页和阅读工具栏的键盘操作。

书架展示作品封面、未读状态和最近阅读信息。点击已读作品，优先恢复上次选中的来源和位置；点击首次阅读作品进入详情选择来源。默认来源失效时展示原因和其他关联来源，由用户重新选择。

### 3.2 搜索与作品详情

发现页提供跨源搜索、源筛选和各源的浏览入口。仅对已启用且具备搜索能力的源发起搜索。结果按返回时间逐步显示，每项标明来源；某源超时或失败不阻塞其他结果。改变查询或离开页面时取消旧请求，旧响应不能覆盖新结果。

详情页展示作品信息、关联来源卡片和书架操作。来源卡片展示站点、该源作品名称、最新章节、最后检查时间及可用状态。用户选择卡片后进入该来源的章节列表，再开始阅读。续读入口明确标示来源及章节。

自动关联参考规范化标题、别名、作者等信息，不因同名直接合并。用户可以搜索并添加其他来源，也可以解除错误关联。各来源的章节数和更新时间分别保留，不合成一个假定统一的章节目录。

### 3.3 阅读器

滚动模式连续展示页面，翻页模式支持左右方向切换。macOS 双页模式按当前方向排列，首页单独展示，之后按顺序成对展示；页面数量为奇数时最后一页独立显示。是否为跨页图片不自动判断。

支持缩放、章节切换、目录、页码、模式切换和背景设置。滚动模式保存页面 ID 与页内位置，翻页模式保存页面 ID。页面图片加载失败时保留占位和重试入口；不跳过失败页或改变页序。

跨源续读根据章节标题和编号提供候选，用户选择后才能更新该来源的进度。没有可靠候选时打开章节列表。切换来源不会覆盖原来源进度。

### 3.4 下载、更新与源管理

下载页按作品、来源、章节显示任务，支持暂停、恢复、取消、失败重试和删除已下载章节。展示完成页数、任务状态与占用空间。

更新页展示书架作品在用户关注来源中新发现的章节；加入书架默认关注当前选中来源，用户可调整。新章节与阅读进度分别记录。首次检查建立基线，不把全部历史章节当作新增；短暂返回空目录不清空旧记录。

源管理支持新增、编辑、启用、停用、重新检测与删除源配置。删除源配置保留已有书架、进度和下载，关联标记为不可在线访问；删除本地漫画资料或下载通过相应页面单独操作。

## 4. 架构与数据边界

共享核心分为源引擎、搜索与作品关联、本地资料库、图片管线、下载管理和更新检查。界面通过服务接口使用核心，不直接解析网页或操作数据库。

建议本地存储采用 SQLite，访问由存储层串行协调并提供迁移。图片文件存入应用容器。自动缓存与用户离线下载分开管理，清理缓存不能删除下载。

主要实体：

| 实体 | 含义与关键关联 |
| --- | --- |
| Source | 网站 URL、稳定源 ID、启用状态、能力、解析绑定 |
| ParserBinding | 解析器 ID / 版本、源配置、验证记录、失效状态 |
| Work | 用户书架中的作品身份与展示资料 |
| SourceWork | 源内作品 ID / URL、原始信息、所属 Source，与 Work 的关联 |
| Chapter | 所属 SourceWork、源内稳定 ID、标题、顺序、可访问状态 |
| PageResource | 所属章节、稳定页 ID、顺序、资源 URL、必要请求上下文及过期信息 |
| ReadingProgress | 所属 SourceWork / Chapter、页面位置、更新时间 |
| DownloadTask | 所属章节、逐页状态、失败原因、本地文件记录 |
| UpdateObservation | 所属 SourceWork、已知章节集合、检查时间、新增记录 |

作品资料和访问凭据分离。Cookie、登录状态等访问上下文仅限对应源在本机使用，不写入普通日志，也不提交到代码仓库。数据库和缓存键使用稳定源、作品、章节、页面身份；临时 URL 更新不产生重复作品或下载任务。

## 5. 解析器、自动匹配与绑定

### 5.1 能力与解析结果

源能力包含浏览、搜索、详情、章节、页面解析。绑定成功不代表拥有全部能力；详情、章节和正文图片验证通过才可标为可阅读。搜索能力独立验证，缺少搜索能力的源仍允许通过作品链接使用。

解析器包括内置站点专用适配器和通用模板解析器。通用模板覆盖已知 HTML / 懒加载图片结构、已知内嵌 JSON 结构，以及明确支持的接口格式；不承诺识别任意网站。HTML 解析建议使用 SwiftSoup。

解析结果输出统一模型。正文页面是有序资源列表，携带所需来源页、请求头和源访问上下文；不把封面、推荐图、广告或 loading 图片当作正文。分页章节必须检查后续页或接口分页，不能把首屏误认为完整章节。

对于需要 JavaScript 渲染的源，可由内置适配器使用受控 WebKit 页面获取正常阅读流程产生的数据。登录或验证需要时展示源页面供用户交互；访问失败保持明确状态，不把验证码、付费页或错误页当作漫画。

### 5.2 自定义源探测流程

1. 验证 URL 格式，保留站点子路径；记录正常重定向后的规范地址，防止重复添加。源身份不只依赖裸域名。
2. 获取页面样本并识别特征，优先尝试对应专用适配器，然后尝试兼容通用模板。样本仅在站点页面公开链接和用户提供链接中选择，探测请求有超时、并发和总数上限。
3. 复用已取得的页面，分别验证作品详情、章节目录和正文页面；读取代表性图片并验证它能被解码，不能只检查 URL 后缀或 HTTP 200。
4. 自动获得足够样本时，在至少两部作品、各两个章节验证一致性；站点内容不足或用户只提供少量样本时，按实际样本绑定并标明有限验证，不宣称普遍可用。
5. 候选以实际读取链路、字段完整性、页序和样本一致性比较。仅有一个明确可用的候选时自动保存绑定；多个候选等价且结果一致时按预设优先级选择；候选正文不一致时让用户通过预览选择。
6. 未找到详情或章节样本时，请用户补充样本链接；方法不兼容时显示未适配。网络或访问限制时显示访问失败，不能报告为没有兼容解析器。

绑定保存解析器版本及必要配置。平时直接使用绑定；版本变化后对现有绑定执行轻量验证。一次超时或单张图失败不会清除绑定；内容结构持续不符合解析规则时标记待重新检测，成功匹配新方法后才替换原绑定。

编辑网站地址后重新验证绑定。停用源会取消新的搜索和探测请求，已有下载保留；进行中的下载按暂停处理。探测取消后不写入半成品绑定。

## 6. 性能、离线与后台行为

网络请求按源限制并发，遵守源返回的重试提示；有超时、退避和取消。搜索、正文解析和图片读取分开调度，正在阅读的页面优先于预取和下载。

图片先显示当前页，再预取后续少量页面。预取窗口随网络与内存状态调整，离开章节时取消无用请求；图片解码和尺寸缩放避免阻塞界面。长条图分段展示或按可视区域加载，不能同时完整解码整章。

离线任务先取得页面顺序，再逐页保存文件，通过临时文件和原子替换避免半文件被当作完成。只有全部所需页面成功保存并可读，章节才能标为已下载；有失败页时保持未完成并允许重试。恢复任务时刷新失效的临时 URL，再根据稳定页身份续传。

下载可以按页继续；源支持 Range 时才对单文件字节续传。取消任务保留可复用的完成页面作为缓存；删除下载清理对应离线文件。磁盘不足时暂停并显示原因，不删除用户下载来腾出空间。

iOS 采用系统支持的后台任务和后台传输机制，不能承诺固定间隔追更或应用被强制退出后仍持续运行。用户回到应用时检查并恢复任务状态，允许手动继续。macOS 在应用运行时可定期检查；首版不安装常驻辅助服务。

更新通知在实际检测到新增章节后发送，按作品和检查批次合并，避免重复提醒；通知权限被拒绝时更新列表继续可用。

## 7. 首批源调研与交付标准

用户指定的首批候选为漫画站、瓜子漫画和 DM5。额外搜索的来源属于候选，不自动扩大首版内置列表；xkcd 可用于结构化接口的技术验证。

截至 2026-10-02 的调研证据：

| 来源 | 已验证 | 尚未解决 |
| --- | --- | --- |
| manhuazhan.com | 浏览工具可读取详情与目录；直接请求首页返回 403 | 正文加载、直接访问条件 |
| guazimanhua.com | 详情 HTML 提供章节链接，章节 HTML 包含 `.reading-image` 和 `img.guazicdn.com` 图片地址 | 图片请求返回 403，提供 Referer 仍未成功；搜索能力尚未验证 |
| dm5.com | 详情与阅读页面可取得；脚本通过 `chapterfun.ashx` 携带章节、页码、时间和签名参数读取图片；站点存在付费内容 | 正文接口响应与图片解码、请求上下文有效期、搜索能力尚未验证 |
| xkcd.com | 官方 JSON 接口返回 HTTP 200，包含标题、日期和 `img` 字段 | 仅为额外候选，不代表中文长篇漫画适配 |

开发先验证真实来源的完整阅读链路，再接入其余功能。每个候选源分别报告支持能力和失败证据；受限源显示具体状态。未完成的源适配保持未完成，不能用模拟图片或无关来源替代其验收。

网站公开免费阅读与第三方应用的使用许可分别核查；后续发布或上架时按实际来源条款确定内置列表。首版不提供解锁付费章节功能。

## 8. 错误处理与验收

面向用户的错误至少区分：网络不可用、超时、源访问受限、需要登录或验证、章节不可访问、解析规则不匹配、图片地址过期、正文图片损坏、磁盘不足。保留书架与已有进度，提供与原因相符的重试、打开源页面、补充样本或重新检测入口。

验证使用脱敏的 HTML / JSON 固定样本检查解析结果，并以在线样本验证真实访问条件；固定样本通过不能替代在线可用性验证。重点验收：

1. 两个平台可编译运行；验证结果分别记录，不能把 macOS 的结果当作 iOS 验证。
2. 跨源搜索逐步返回，单源失败不阻塞其他源，旧查询不覆盖新查询。
3. 来源关联可合并、拆分，选择来源后进入正确章节；各来源进度不会相互覆盖。
4. 自定义源从检测到绑定再到重复使用可完成，多个候选、有限样本和访问失败有明确结果。
5. 广告、封面、验证页不能通过正文判定；分页、页序和临时地址刷新正确。
6. 滚动、翻页、方向切换、macOS 双页和退出续读保持正确位置。
7. 已下载章节断网可读，任务中断后可恢复；缓存清理不损坏离线内容；损坏页不标为完成。
8. 更新首轮只建立基线，后续新增章节能识别；通知不重复，空目录响应不删除旧资料。
9. 测量冷启动阅读的首图时间、连续阅读等待和内存峰值，记录设备与网络条件；不在测量前承诺速度提升比例。

当前机器已验证 Swift 6.2.4 和 Command Line Tools 可用，标准应用目录未发现完整 Xcode。共享核心可先进行本地构建与测试；iOS 应用构建、模拟器及签名安装验证需要完整 Xcode 环境。该条件是后续实施的环境依赖，设计稿阶段不安装工具。
