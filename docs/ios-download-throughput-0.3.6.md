# v0.3.6 iOS 离线下载吞吐优化

## 实际问题与改动

本次使用连接的 iOS 18.5 设备上“斗破苍穹”的瓜子漫画下载任务定位问题，未修改图片地址、图片质量或漫画来源。

[Apple 的后台下载说明](https://developer.apple.com/documentation/foundation/downloading-files-in-the-background)指出后台传输由独立进程执行，每个任务都有开销，后台唤醒后的新任务还可能受到系统延迟调度。本次前台通道优化由真实图片请求测量定位。

- 旧实现即使在 App 前台，也把每张公开图片交给系统后台会话，数千个小文件不断支付跨进程调度开销。现在前台复用受控 HTTP 客户端及连接池，继续使用来源与域名隔离的凭据、重定向策略、取消及 `Retry-After` 重试。
- 前台请求执行中若 App 切入后台，会取消并等待该前台请求结束，再以相同任务、目的文件接入原生后台下载；已有原生任务与已落盘完成记录优先复用。iOS 的有限后台执行时间由传输本身申请和释放，不依赖界面刷新状态。带凭据的请求仍使用受控客户端。
- 每章可并发 6 张图片，同源图片上限 6、所有图片上限 8；共享网络调度上限 10，同源上限 7，下载/预取保留至少 2 个全局、1 个同源名额供交互使用。章节准备与图片共享上述网络预算；每部漫画仍最多运行 2 个章节，保留多作品公平分配。
- 旧版重启会强制重新解析所有待下载章节。实机观察到章节站返回 403，而抽样图片 CDN 正常响应，导致待下载队列失败。现在重启优先复用公开图片列表，过期地址及临时访问上下文仍重新解析；用户明确点击重试时仍刷新章节列表。旧版遗留的强制刷新 403、且仍有公开图片列表的任务会恢复一次直接下载尝试；不会恢复用户暂停的任务。开始图片请求前保存已清除的刷新标记，避免下次启动反复自动重试。
- 保留图片完整性校验、按页面续传、离线文件、阅读进度、书架和原有连续阅读行为。设备系统版本保持不变。

## 验证

219/219 项共享检查、`swift test` 的 34 个参数化入口通过，覆盖范围有重叠。新增真实本地 HTTP 检查：公开图片限流重试、后台路由、凭据请求受控传输、前台请求未完成时切到后台、切换时取消。下载恢复检查覆盖 CDN 可用而章节页 403、旧失败记录恢复、暂停状态保留、排队中的手动重试跨重启保留刷新要求，以及过期/临时访问上下文必须刷新。原有离线损坏检测、签名刷新、章节重排和暂停续传检查继续通过。

同一部作品的实机队列观测：旧版两个数据库快照间下载约 39.71 MB，用时约 249.36 秒，约 159 KB/s；优化后连续完成的 174 话约 332.96 MB，完成记录时间窗口约 604.01 秒，约 551 KB/s。当次观测约为原来的 3.5 倍。手机原有 250 话任务最终全部完成，共 3456 页，约 596 MB。

上述窗口包含章节解析、图片传输、校验与落盘，但前后并非相同时间的受控网络实验，不能视为固定提速倍率。网站或 CDN 限流、图片体积、设备与网络变化、手机后台调度仍会影响实际速度。另有本机相同 12 张图片的链路抽样用于定位后台通道开销；不将 Mac 抽样速度当作 iPhone 实测速率。

最终 0.3.6（build 12）已在连接的 iOS 18.5 设备覆盖安装、确认版本并启动；原有下载队列与离线记录保留。macOS Universal 和 iOS Release 包均通过严格签名及压缩包完整性检查。

签名、设备标识、下载数据库及原始测量样本仅保存在忽略目录，不进入公开源码。构建固定 Xcode 16.4，最低 macOS 14 / iOS 17，适配现有 macOS 15.7.7 / iOS 18.5。
